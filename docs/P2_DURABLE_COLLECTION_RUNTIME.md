# P2 可靠落库与常驻采集实施记录

日期：2026-10-09

## 本阶段完成

- JetStream 原始行情与标准行情两个持久消费者。
- 显式消息确认、最多5次重试、失败死信和失败即停的批量验证模式。
- 原始事件幂等写入 `market.raw_events`。
- 合约、交易状态和规则版本写入 `core`，规则内容未变化时不产生新版本。
- 全量合约目录事件用于识别 Binance 已移除合约并标记 `DELISTED`。
- 1分钟Ticker写入，同时从同一决策数据集写入资金费率。
- 5分钟K线写入；内容变化时保留旧版本并产生新修订版本。
- 5分钟全市场OI采集，保存Binance实际数据时间、原始数量、标记价格换算的USDT名义价值和质量状态。
- 每个UTC 5分钟边界复用同一份Ticker响应生成滚动24小时涨幅榜前50，不增加Binance请求。
- 独立UTC自然日榜守护服务使用本地完整5分钟Trade K线生成23:55日榜，启动时自动补漏，缺口修复后自动重算。
- 独立缺口检测与自动回补守护：任务抢占、状态审计、写入后复核、失败留痕和重叠范围去重。
- 回补积压存在时连续处理，队列清空后恢复配置化扫描间隔。
- NATS消费者同时处理库专用与标准异步超时，连接中断后无限重连，避免空闲或基础设施重启导致消费者退出。
- 修复Pydantic多态载荷被序列化为空对象的问题，并增加回归测试。
- 常驻调度器：启动等待5秒、每分钟Ticker、每5分钟K线、UTC 16:00规则全量同步。
- Docker Compose `collector`、`market-writer` 与 `data-repair` 守护服务，异常退出自动重启。

## 真实验证

- 有效合约目录：659个 USDT 永续合约，其中525个处于 `TRADING`。
- 同一批11条原始事件和664条标准事件重放后，数据库记录数保持不变，幂等验证通过。
- 全量常驻采集覆盖525个正常交易标的。
- 人为删除BTCUSDT一根5分钟K线后，系统成功检测、从Binance回补并将缺口标记为`VERIFIED`。
- 停机产生的全市场真实缺口被自动识别并排队；连续回补实测每轮成功50项且不生成重叠任务。
- OI首轮覆盖525个正常交易合约，全部具有USDT名义价值且质量为`VALID`。
- UTC 14:30和14:35滚动榜单实测各50项、质量为`VALID`，相同快照键幂等更新。
- `ruff`、严格 `mypy` 和17个测试全部通过。
