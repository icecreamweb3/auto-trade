# P0 数据库容量与12个月读取PoC

> 执行日期：2026-10-09  
> 环境：本地 Docker，PostgreSQL 16.15，TimescaleDB 2.30.1  
> 原始输出：`artifacts/p0_database_capacity_20261009T041539Z.log`

## 测试范围

- 使用独立 `benchmark` Schema，不写入V2正式业务表。
- 生成10个合成ticker，每个ticker包含完整12个月的1分钟记录。
- 覆盖区间：`2025-01-01 00:00:00 UTC` 至 `2025-12-31 23:59:00 UTC`。
- 总记录数：5,256,000。
- Hypertable按7天分块，共53个chunk。
- 每条记录包含成交价、标记价、指数价、24小时涨幅、成交额、资金费率、OI和payload hash等近似字段。

## 实测结果

| 指标 | 结果 |
|---|---:|
| 526万行服务端批量生成写入 | 26.495秒 |
| 等效写入吞吐 | 约198,377行/秒 |
| ANALYZE耗时 | 4.916秒 |
| Hypertable总空间 | 1,061,543,936字节，约1012MB |
| 平均每行空间 | 约201.97字节 |
| 500 ticker同表年度空间粗估 | 约49GB |
| 单ticker完整12个月聚合扫描 | 约56.1毫秒 |
| 单ticker完整12个月聚合为15分钟OHLC | 约217.1毫秒 |

## 结论

1. 当前本机数据库具备进入采集服务开发阶段的基础写入与时间范围读取能力。
2. 按500个ticker估算，只有 `ticker_minutes` 一类数据约需49GB/年；K线、OI、资金费率、原始事件、索引、WAL、备份和未来修订版本须另行计入，不能把49GB作为系统总容量。
3. 写入测试使用数据库端 `generate_series`，反映数据库批量写入上限，不代表Binance网络采集端到端吞吐；采集服务完成后必须补做网络、事件流、批量写入并行压力测试。
4. 查询测试命中本地缓存，属于热数据结果。正式云部署规格确定前还需执行冷缓存、混合读写和回测并发压力测试。
5. 现有7天chunk能够将单ticker全年查询拆分为53个chunk，并保持百毫秒级聚合；后续根据真实数据量和压缩效果再决定是否调整chunk周期。
