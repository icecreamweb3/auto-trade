# P3 1分钟 Trade/Mark K线实施记录

日期：2026-10-10

## 本阶段完成

- 全部正常交易 USDT 本位永续合约订阅 Trade 1m 与 Trade 5m WebSocket闭合K线；Mark 1m由全市场`!markPrice@arr@1s`实时流按UTC分钟本地聚合OHLC。
- 24h ticker、mark price、index price、资金费率和下次费率时间使用全市场WebSocket流缓存，每分钟从同一份缓存形成快照及滚动涨幅榜。
- WebSocket 按可配置上限分片，标的目录在 UTC 16:00 更新后自动重建订阅。
- Futures 行情使用已实测的 `/market/stream?streams=...` 组合流路径，并显式传递代理配置。
- WebSocket 断线指数退避；连接成功但15秒无行情也视为异常，避免静默失效。
- 生产调度不再按标的使用REST轮询可由WebSocket提供的ticker及K线；REST只保留合约规则、OI、缺口回补和必要核对。
- Trade/Mark 使用统一 `KLINE_CLOSED` 契约、确定性事件ID、JetStream 与版本化K线表。
- REST客户端按IP每分钟2,400权重上限记录本进程60秒请求数、Binance返回的`x-mbx-used-weight-1m`及上限；原始事件也保存请求速率和已用权重。
- 已用权重达到80%（1,920）时主动暂停60秒；`429/418`不再快速重试，统一遵守`Retry-After`并在进程内阻塞后续REST请求。
- 缺口检测及 REST 回补覆盖 Trade 1m、Mark 1m、Trade 5m，并兼容既有5m任务。
- 缺口扫描落后一个源周期，避免与实时写入竞态产生假缺口。
- 缺口扫描与积压消费解耦：扫描仍按5分钟执行，存在积压时连续处理，同时每个实际REST回补请求至少间隔2秒。
- 回补前先检查数据库实际覆盖；数据已由其他路径写入时直接核验完成，不再重复请求Binance。
- 调度优先处理小缺口，并按数据类型完成进度进行公平排序，避免单一Trade队列长期阻塞Mark。
- 写入确认窗口默认延长至60秒且可配置，降低JetStream有积压时的误判和重复回补。
- 服务启动及定期扫描会恢复超时`RUNNING`任务，并在配置的次数内重试`FAILED`任务。
- 全市场WebSocket报文按当日合约目录中的`TRADING`白名单过滤，非正常交易或已下架标的不再产生新的实时记录。
